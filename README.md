# KAOS-RT

[![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)
![Language: ISO C17](https://img.shields.io/badge/language-ISO%20C17-informational.svg)
![Status: Technical preview](https://img.shields.io/badge/status-technical%20preview-orange.svg)

KAOS-RT — компактное кооперативное ядро для одноядерных 32-разрядных
микроконтроллеров. Оно помогает строить прикладное ПО как набор конечных
автоматов: автомат получает накопленную маску событий, выполняет короткий шаг
и возвращает новое состояние. Память под автоматы и таймеры выделяется
статически, а порядок их обслуживания фиксирован.

Ядро подходит для устройств с датчиками, интерфейсами, реле, приводами и
коммуникационными протоколами. Прикладная логика строится из коротких шагов,
которые вызываются по событию.

## Когда выбрать KAOS-RT

KAOS-RT не заменяет вытесняющую RTOS. Он предназначен для одноядерных
событийных систем, где работу можно представить короткими шагами конечных
автоматов и где важны прозрачный порядок исполнения, статическая память и
простота анализа.

## Основные свойства

- Статическая память — количество автоматов и таймеров задаётся при сборке; динамическая память не используется.
- События — до 32 объединяемых событий на автомат; `append_event()` безопасна для вызова из IRQ.
- Таймеры — одноразовые и периодические, с постановкой маски событий по истечении срока.
- Диспетчер — автоматы обслуживаются в фиксированном порядке по ID.
- Порты — [STM32F407](port/stm32f407/README.md), CH32V20x, CH32V30x и POSIX.

## Как начать

1. Возьмите `fsm.c`, `fsm.h`, `fsm_config.h` и порт нужной платформы.
2. В конфигурации платы задайте частоту аппаратного источника времени, если её требует выбранный порт.
3. Объявите в приложении `fsm_id_t` и `fsm_event_t` в `fsm_instance.h`.
4. Инициализируйте платформу и вызовите `start_fsm()`.
5. Зарегистрируйте функции автоматов через `set_fsm()`.
6. Вызовите `main_fsm()` из `main()`.

Примеры проектов находятся в
[`example/stm32f407-black-board/`](example/stm32f407-black-board/) и
[`example/posix/`](example/posix/).

| `port/` | Реализации платформенной части. |
| `example/` | Минимальный запускаемый проект. |
| `docs/` | Контракт, перенос на новую платформу и правила вклада. |
