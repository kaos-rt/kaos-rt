# Перенос KAOS-RT на новую платформу

Порт соединяет ядро с архитектурой микроконтроллера. Он не содержит прикладной
логики и не меняет публичный API KAOS-RT.

## Состав порта

Порт размещается в `port/<семейство_МК>/`. Минимальный вариант содержит
`fsm_port.h`. Если для реализации требуется код с внешним связыванием, рядом
размещается `fsm_port.c`.

Заголовок порта определяет:

- `fsm_irq_state_t` и `fsm_profile_tick_t`;
- `fsm_port_time_init()` и `fsm_port_time_now()`;
- `fsm_port_irq_save()` и `fsm_port_irq_restore()`;
- `fsm_port_profile_init()` и `fsm_port_profile_now()`;
- `FSM_PORT_WEAK`;
- `FSM_PORT_EVENT_POLL_REQUIRES_IRQ_LOCK`.

Типы `fsm_time_t` и `fsm_duration_t` принадлежат ядру и объявляются до
подключения `fsm_port.h`. Порт возвращает `fsm_time_t`; прикладной код задаёт
интервалы типом `fsm_duration_t`.

## Время

`fsm_port_time_now()` возвращает младшие 32 бита монотонного счётчика логических
тиков. Частота задаётся `FSM_TICK_FREQ_HZ`. Выбранный источник времени должен
работать непрерывно после `fsm_port_time_init()`.

Частота самого аппаратного источника времени задаётся конфигурацией платы или
её сборки, а не портом: она зависит от МК и дерева тактирования. Порт не должен
выбирать для неё значение по умолчанию.

Для аппаратного таймера порт проверяет его частоту, разрядность предделителя и
режим свободного счёта на этапе компиляции. Порт не использует callback таймера
для обслуживания KAOS-RT.

## Критическая секция

`fsm_port_irq_save()` сохраняет состояние разрешения IRQ и создаёт критическую
секцию. `fsm_port_irq_restore()` восстанавливает именно сохранённое состояние.
Вложенный вызов сохраняет корректность внешней критической секции.

Порт должен обеспечивать атомарность постановки события из IRQ относительно
захвата диспетчером ожидающей маски. Если быстрый опрос маски без блокировки
небезопасен на выбранной платформе, задаётся
`FSM_PORT_EVENT_POLL_REQUIRES_IRQ_LOCK` равным `1`.

## Профилирование

Функции профилирования возвращают монотонные тики подходящего аппаратного или
системного счётчика. Они требуются для сборки с `FSM_PROFILE_ENABLE == 1`.
В релизной сборке с `FSM_PROFILE_ENABLE == 0` данные функции не влияют на
поведение приложения.

## Слабая функция

`FSM_PORT_WEAK` объявляет поддерживаемый компилятором атрибут слабого символа.
Он используется для пустой реализации `fsm_loop_service()`, которую приложение
может заменить собственной функцией.

## Проверка нового порта

Перед применением в изделии проверьте:

1. запуск и монотонность источника времени;
2. сохранение состояния IRQ при вложенных критических секциях;
3. постановку события из реального IRQ;
4. создание и истечение одноразового и периодического таймера;
5. соответствие частоты таймера настройкам тактирования платы.

Имя каталога порта указывает на реально поддерживаемое семейство. Например,
`stm32f407` обозначает порт для STM32F407, а не для всех STM32.
